# Review: Minecraft 1.21.5

An independent review by a FRESH agent that was given only this target's files (STUBS.json, its overlays,
the authors' files they replace, its resource overlays and renames.tsv). One row per STUBS.json entry,
per whole-file overlay, per resource group (`resources`: a directory of the target's resources/, with the
digest of its files -- an edit makes it a new row) and for renames.tsv (`renames`, with its digest);
verdict `ok` (the change keeps the authors' behaviour, or the difference is right and the note says why)
or `not-ok` (it does not: the target is not done). A hook item of the behaviour inventory (a mixin target,
an injection, an event listener, a shader uniform/sampler) is accounted for only by a row whose note names
its id, or by an `item` row for the id. `reviewer` names the reviewing agent, distinct from the fixer
(e.g. `fresh agent <id>, not the fixer`). `commit` is the commit reviewed, a hex id of 7-40 digits
(`git rev-parse --short HEAD`). tools/fork-port.py adds a `?` row for every item it finds unreviewed
(an `item` row for every unaccounted inventory item); it never changes a verdict.

## Findings (reviewer)

Both are in the shared 1.21.5 library (`.multiversion/shared/1.21.5/java/net/eca/mv/`), not in this target's overlays;
every overlay's own change is right. They are recorded on the 24 `shader` items because they decide whether each
preset's effect still draws.

**F1 -- a RenderType's setupRenderState no longer sets its shader or its state.** 1.21.1 draws a queued extension pass
as `pass.renderType().setupRenderState(); BufferUploader.drawWithShader(mesh)` (src/main/java/net/eca/client/render/
ShaderMaskRenderQueue.java:116-118; also EcaBossBarRenderer.java:277-289 and GameRendererPostLevelMixin's post-level
skybox), where the CompositeState's ShaderStateShard does `RenderSystem.setShader` (1.21.1 RenderStateShard.java:594)
and its transparency/depth/write-mask/cull shards set GL state. On 1.21.5 the prepared ShaderMaskRenderQueue.java:113-115
is `setupRenderState(); LegacyGl.drawWithShader(mesh)`, but LegacyRenderType's setup runnable runs only `state.real`
(texture/lightmap/overlay; shared/1.21.5 LegacyRenderType.java:99-100) -- the ShaderShard and the Key are used only in
`draw()` (:107-111). So drawWithShader (LegacyGl.java:119) draws with LegacyGl's static `shader` -- whichever shader the
last draw set, or none ("[mv] a draw with no shader set was skipped") -- and LegacyGl.current() (static blend/depth/
depth-write/cull), and the mod's ShaderShard override (XShader.applyUniforms: CameraYaw/Pitch, ColorKey, LocalUv) never
runs for the pass. Every extension shader pass goes through this draw: entity (EntityExtensionLayer.drawNow), item
(ItemRendererMixin), block and falling block (BlockExtensionRenderer, FallingBlockRendererMixin), Geo layers, plus the
